# Mentor Automator

[![Checks](https://github.com/tg-prplx/mentor-automator/actions/workflows/ci.yml/badge.svg)](https://github.com/tg-prplx/mentor-automator/actions/workflows/ci.yml)

Локальный помощник для Moodle Mentor: раз в 5 минут проверяет курсы, уведомляет в Telegram и по вашей кнопке обрабатывает вопросы в видимом браузере. Завершение попытки требует отдельного одноразового подтверждения.

**По умолчанию работает через Codex CLI с входом через ChatGPT: API-ключ не нужен.** Нужен аккаунт с доступом к Codex; используются его лимиты. Окно приложения Codex не заменяет установленный CLI. Можно выбрать и локальный OpenAI-совместимый сервер.

## Быстрый старт

### 1. Скачайте проект

Нажмите **Code → Download ZIP** на GitHub и распакуйте архив в отдельную папку. Или используйте Git:

```sh
git clone https://github.com/tg-prplx/mentor-automator.git
cd mentor-automator
```

### 2. Один раз установите необходимые программы

Нужны [Google Chrome](https://www.google.com/chrome/), [uv](https://docs.astral.sh/uv/getting-started/installation/), [Node.js LTS](https://nodejs.org/) и Codex CLI. Python 3.12 и зависимости проекта uv установит сам.

**macOS с Homebrew:**

```sh
brew install uv node
npm install -g @openai/codex@0.160.0
codex login
```

Если Homebrew нет, установите uv по официальной инструкции по ссылке выше, Node.js — с официального сайта. После установки откройте новое окно Terminal и выполните две последние команды.

**Windows 10/11 — PowerShell:**

```powershell
winget install --id astral-sh.uv -e
winget install --id OpenJS.NodeJS.LTS -e
# Закройте и заново откройте PowerShell, затем:
npm install -g @openai/codex@0.160.0
codex login
```

В окне входа выберите ChatGPT. Доступ зависит от аккаунта и организации; приложение не извлекает токены из других приложений и не использует неофициальный API ChatGPT. Установка и вход описаны в [официальной инструкции Codex](https://learn.chatgpt.com/docs/cli) и [справке по авторизации](https://learn.chatgpt.com/docs/auth). Защитные параметры проверены с CLI 0.160.0; эта версия указана в командах намеренно.

### 3. Откройте файл запуска

| Система | Запуск из распакованной папки |
|---|---|
| macOS | Двойной клик по **start.command** |
| Windows | Двойной клик по **start.bat** |
| Linux | `bash start.command` из терминала |

Если macOS не разрешает открыть файл или ZIP потерял право выполнения, откройте Terminal в папке проекта и выполните `bash start.command`. Запускатель скачает Python 3.12 и установит зависимости из `uv.lock`. Сборка Chromium нужна только для тестов или явного `BROWSER_CHANNEL=chromium`; обычное приложение использует установленный Chrome.

При первом запуске мастер:

1. Попросит создать своего бота через **@BotFather → /newbot** и ввести его токен. Ввод скрыт.
2. Попросит логин и пароль Moodle, сохранит их только в локальном `cred.txt`. Уже существующий файл не читает и не перезаписывает.
3. Покажет одноразовую команду `/pair ...`. Отправьте её своему боту **в личном чате**, чтобы привязать Telegram без ручного поиска ID.
4. Проверит установку Codex и браузера, затем откроет видимый Chrome. Самостоятельного начала теста не будет.

При последующих запусках мастер пропускается. Панель отключена по умолчанию; управление и прогресс — в Telegram. Не закрывайте окно терминала: процесс работает, пока окно открыто. `Ctrl+C` останавливает приложение без программной отправки незавершённой попытки. Одновременно допускается один экземпляр с одним каталогом данных и один long polling на токен бота.

### 4. Откройте своего бота

Отправьте `/tests`, выберите тест кнопкой **«пройти тест»** и наблюдайте за видимым браузером. На последней странице агент остановится: **отправка возможна только после вашего отдельного нажатия «подтвердить завершение»**. Сервер Moodle может закрыть попытку сам при истечении времени.

## Если запуск не удался

Из папки проекта:

```sh
uv run mentor --doctor       # установка и вход Codex, чистый временный браузер; без входа в Moodle
uv run mentor --setup        # повторить незавершённую настройку
uv run mentor --check-codex  # синтетический вопрос; расходует лимит Codex
uv run mentor --launch      # мастер при необходимости и обычный запуск
```

`--doctor` проверяет только наличие `cred.txt`, не открывая его. Ошибки токена и связи с Telegram во время привязки не считаются успешной настройкой. Не запускайте привязку или проверки Telegram параллельно с уже работающим ботом. Чтобы заменить токен, отредактируйте локальный `.env` самостоятельно и повторите привязку; свои файлы публиковать не нужно.

Для ручной установки вместо запускателей: `uv sync --locked --python 3.12`, затем `uv run mentor --setup` и `uv run mentor`. Настройки находятся в `.env`; безопасный шаблон — `.env.example`. Формат данных входа приведён только с вымышленными значениями в `cred.example.txt`:

```ini
username=student.demo
password=fictional_password_replace_locally
```

Пароль может содержать `=`; файл сохраняется в UTF-8. `.env`, `cred.txt`, база, браузерный профиль и снимки остаются на вашем компьютере. После первого входа сессия сохраняется локально; истёкшая сессия потребует повторной авторизации.

## Как пользоваться

1. При старте и затем каждые 300 секунд приложение проверяет список курсов, страницы курсов и индекс тестов. Мониторинг использует отдельную страницу и продолжается во время работы агента. Проверки не накладываются друг на друга; если один обход дольше пяти минут, следующий начнётся после него.
2. Новый тест или изменение известных сведений записываются в SQLite и отправляются в Telegram. Вы увидите дисциплину, название, доступность, срок, лимит времени, оставшиеся попытки и ссылку. Неизвестные значения помечаются явно; отсутствие кнопки не интерпретируется как достоверная доступность.
3. Только ваше нажатие **«пройти тест»** запускает агента. Сначала используется существующая попытка, если Moodle показывает кнопку её продолжения. Иначе агент нажимает кнопку начала. Такой запуск может сразу запустить таймер и потратить попытку.
4. Браузер видим. Telegram редактирует сообщение прогресса с ограничением частоты: вопрос, выбранный ответ, уверенность, обоснование, счётчики и таймер. Дополнительная панель показывает те же данные, если вы явно включили её.
5. После последней определённой страницы состояние становится `AWAITING_FINAL_CONFIRMATION`. Агент останавливается **перед** кнопкой завершения/переходом к сводке. В Telegram приходят три кнопки: **«подтвердить завершение»**, **«продолжить проверку»**, **«отменить»**.
6. Только первая кнопка разрешает переход к сводке и окончательную отправку этой попытки. Вторая запускает повторный анализ с первой доступной страницы и затем выдаёт новое подтверждение. Повторная проверка может изменить ранее выбранные ответы. «Отменить» останавливает программу для этой попытки, сохраняя её на Moodle без программной отправки.

Плавное движение курсора, прокрутка, ожидание элементов и небольшие вариативные задержки предназначены для наблюдения. Подмена отпечатка, сокрытие WebDriver, обход CAPTCHA, SEB или антибот-защиты не реализованы. Препятствия этого типа требуют ручного вмешательства. Используйте помощник там, где правила курса разрешают такую помощь.

## Команды Telegram

| Команда | Действие |
|---|---|
| `/start`, `/help` | Справка |
| `/tests` | Один список по 5 тестов: стрелки, фильтр доступных/всех, кнопки запуска. Повторная команда редактирует этот же список |
| `/status` | Состояние, ID попытки, счётчики, таймер, состояние мониторинга |
| `/pause` | Приостановить действия; отозвать подтверждение |
| `/resume` | Продолжить после паузы или восстановить сохранённую попытку |
| `/review` | Повторно проверить доступные страницы, затем запросить новое подтверждение |
| `/stop` | Остановить агента, не отправляя попытку |
| `/scan` | Запросить проверку курсов |
| `/diagnostics` | Только количество совпадений настроенных селекторов на странице попытки |

Локальная панель предоставляет паузу, продолжение, остановку и мониторинг. Кнопки финального подтверждения на панели нет. Пауза не останавливает часы сервера Moodle. Запрос к модели, уже выполнявшийся в момент паузы, может завершиться, но ответ не применяется до возобновления. При остановке дочерний процесс Codex завершается вместе с дочерними процессами.

## Защита завершения и восстановление

- Подтверждение связано с ID запуска и ID попытки. В SQLite хранится SHA-256 одноразового случайного токена и время истечения (по умолчанию 15 минут). Нажатие атомарно переводит ровно одну запись в `SUBMITTING` и удаляет токен.
- Повторная кнопка, другая попытка, другая учётная запись Telegram, истёкший токен и токен до перезапуска не подходят. Новое разрешение получают через `/review` после открытия и проверки попытки.
- Перезапуск сохраняет `AWAITING_FINAL_CONFIRMATION`, но отзывает все токены. `RUNNING`, `PAUSED`, `STARTING`, `ERROR`, `SUBMITTING` становятся `RECOVERY_REQUIRED`. Самостоятельное продолжение и повтор отправки запрещены.
- Последняя страница сохраняется обычной формой Next перед переходом к сводке. Форма окончательной отправки определяется по `processattempt.php` и `finishattempt=1`, независимо от языка кнопки. Окно Moodle ожидается по фактической видимости; поддерживаются YUI-confirm, модальные подтверждения и native confirm, привязанный к разрешённому финальному нажатию. Посторонние native confirm отклоняются.
- Перед каждым завершающим нажатием проверяется доступность Telegram; отдельный watchdog проверяет связь каждые 15 секунд. Обнаруженная потеря связи отзывает разрешение и ставит выполнение на паузу. При ошибке отправки запроса подтверждения токен также отзывается.
- Независимый сетевой перехватчик блокирует `summary.php`, `finishattempt`, `timeup`, переход `nextpage=-1`, неизвестные операции записи в модуле тестов и непрозрачные формы, пока разрешения нет. Разрешение действует до 60 секунд и допускает одну завершающую запись. Произвольные Moodle AJAX-сервисы во время активной попытки блокируются; стандартный `autosave.ajax.php` разрешён.
- Сетевой сбой в ходе отправки даёт `RECOVERY_REQUIRED`. Программа не повторяет действие автоматически: сначала проверьте фактический результат на Moodle. Запрос, уже принятый сервером, нельзя отозвать остановкой приложения.
- Сервер Moodle может закрыть попытку по времени независимо от программы и доступности Telegram. Панель читает таймер интерфейса; предупреждения отправляются при остатке 5 минут и 1 минуты. Блокировка клиентского `timeup` не продлевает серверный срок.
- Состояние `COMPLETED` означает обнаруженную страницу подтверждённой отправки, а не правильность всех ответов. Неизвестные типы и ответы ниже `MIN_CONFIDENCE` по умолчанию ставят агента на паузу для ручного ответа. Явная настройка `UNCERTAIN_ANSWER_POLICY=skip` разрешает пропуск без паузы. Уверенность модели — самооценка, а не гарантия.
- Повторная доставка одного Telegram-события «Пройти тест» после перезапуска отсекается по сохранённому ID события; один callback не запускает попытку повторно.
- Файловая блокировка запрещает второй процесс с тем же `DATA_DIR`; глобальная блокировка запусков и частичный уникальный индекс запрещают двух активных агентов для одной попытки. Используйте один экземпляр приложения для аккаунта.

Если ID не был получен до сбоя, `/status` показывает этап, безопасную причину и отдельную кнопку «Повторить запуск». Нажатие этой кнопки — явная команда пользователя; для того же теста используется существующая запись запуска, поэтому старый `ERROR` не блокирует повтор. `/resume` без ID ищет только продолжение уже существующей попытки и никогда не нажимает начало новой. Ни `None`, ни сырое исключение Playwright пользователю не показываются. Ошибка завершения сохраняет отдельный этап и безопасный код причины. Кнопка восстановления использует сохранённые ответы и затем выдаёт новое одноразовое подтверждение; старое разрешение повторно не применяется. При закрытом браузере перезапустите приложение, затем `/review`. Для тестов с последовательной навигацией сервер может запретить возврат на первую страницу: проверяйте их вручную; приложение не обходит ограничение.

Для Mentor проверена реальная разметка начала: видимая «Спроба тесту» и скрытая «Почати спробу» в форме подтверждения. Начальная кнопка определяется также по форме `/mod/quiz/startattempt.php`. Подтверждение нажимается только после появления видимого элемента; поддерживается отдельное окно попытки Moodle. Этот двухступенчатый сценарий и задержка появления модального окна проверены на локальном макете. Проверка `uv run mentor --inspect-start` читает только структуру кнопок последнего теста и не начинает попытку.

После открытия страницы приложение ждёт загрузки DOM и видимого контейнера вопроса до 15 секунд. Переход вперёд ожидает изменения URL и загрузки документа вместо фиксированной короткой задержки. Обычные формы сохранения `multipart/form-data` разбираются в памяти: защита проверяет только ID попытки, направление перехода и флаги завершения. Неоднозначные или непрозрачные формы блокируются; эта ошибка имеет отдельный код `SAVE_REQUEST_BLOCKED`.

`uv run mentor --inspect-attempt ID` читает структуру указанной сохранённой попытки с блокировкой изменений (без ID — последней); отчёт содержит счётчики, типы вопросов и признаки страницы просмотра. `uv run mentor --resume-existing ID` восстанавливает только уже сохранённый ID в состоянии ошибки/паузы/восстановления. При закрытой попытке или несовпадении ID запуск прекращается. Самостоятельно новую попытку эта команда не создаёт.

Восстановление только ожидания отправки: `uv run mentor --prepare-finish ID`. Команда проверяет уже сохранённую попытку, не меняет ответы, не вызывает модель и не отправляет тест; выдаёт новое одноразовое подтверждение Telegram. Подходит только для запуска, ранее дошедшего до финального этапа. Если Moodle уже показывает закрытую попытку, новое подтверждение не выдаётся. `/status` показывает управляемую попытку, даже если в истории есть более новая пустая запись запуска.

Сетевая защита отдельно учитывает заблокированные запросы теста и фоновые запросы интерфейса. Загрузка переводов и шаблонов штатного окна подтверждения Moodle разрешена явным списком сервисов; неизвестные операции остаются заблокированными. Ошибка фонового запроса не считается доказательством сбоя отправки теста. При сбое сохраняются только безопасные признаки запроса (категория, наличие совпадающего ID, состояние разрешения), без URL, тела запроса, значений ответов и сессионных данных.

## Типы вопросов и изображения

| Тип | Действия и проверка |
|---|---|
| Один / несколько вариантов, true-false | Выбор видимых контролов и проверка checked; порядок вариантов читается заново |
| Короткий текст, число, видимый textarea | Заполнение и проверка значения; числовые ответы должны быть конечными числами |
| Matching / выпадающие списки | Отдельное соответствие для каждой строки, проверка selectedIndex |
| Gapselect / пропуски | Условие содержит локальные метки полей; каждый список заполняется отдельно |
| Cloze / embedded answers | Несколько текстовых полей, списков и групп radio/checkbox внутри одного вопроса |
| Ordering | Кнопки перестановки стандартного Moodle или движение мышью; проверяются DOM-порядок и настоящее поле ответа |
| DDWTOS / слова в пропусках | Перетаскивание мышью, при необходимости штатные клавиши Moodle; проверка всех placeinput после заполнения |
| DDImageOrText / подписи на изображении | Снимок с локальными метками источников и зон; учёт групп и разрешённых повторов, проверка полей ответа |
| DDMarker / координатные маркеры | Модель получает фон без полей страницы и координаты 0..1; учитываются лимиты копий, сверяются реальные координаты, повторное заполнение очищает прежние позиции через UI |
| Информационные блоки Description | Читаются как информация, не отправляются модели и не считаются пропущенным вопросом |

Разметка адаптеров сверена с исходниками Moodle 4.5: [matching](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/question/type/match/renderer.php), [ordering](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/question/type/ordering/templates/formulation_and_controls.mustache), [DDWTOS](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/question/type/ddwtos/renderer.php), [DDImageOrText](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/question/type/ddimageortext/rendererbase.php), [DDMarker](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/question/type/ddmarker/renderer.php). Старый вариант ordering без кнопок проверяется отдельным сценарием с мышью. Это не означает совместимость с каждым сторонним плагином или изменённой темой.

Картинки в условии и вариантах загружаются до снимка. Модель получает только область конкретного вопроса, формулы, таблицы и доступные подписи. Для координатных маркеров снимок ограничен самим фоном, чтобы координаты не считались относительно белых полей страницы. Хеши изображений используются локально для обнаружения подмены; URL изображений, Moodle-имена и значения контролов не входят в JSON модели. Если условие, варианты или изображения изменились после анализа, подготовленный ответ не применяется.

`UNCERTAIN_ANSWER_POLICY=pause` действует по умолчанию: неизвестный тип, недоступное изображение, отказ модели отвечать или уверенность ниже порога приводят к паузе и одному сообщению Telegram. Заполните вопрос вручную в браузере и нажмите «Продолжить после ручной проверки» или используйте `/resume`. Ручной вопрос учитывается как пропущенный агентом, поскольку его правильность программа не подтверждает. Старая кнопка продолжения не действует на следующую паузу или после перезапуска. Таймер сервера во время ожидания продолжает идти.

JSON ответа содержит `choices`, `text`, `explanation`, `confidence`, `skip`, а также пустые или заполненные `assignments`, `order`, `placements`. Для каждого поля задаётся отдельный ответ; неизвестные ID, дубли, недопустимые повторения drag-элементов, лишние координатные копии и координаты вне 0..1 отклоняются до действий браузера.

## Приватность

`auth.py` — единственное место, открывающее `cred.txt`, только во время входа готового приложения. Сначала проверяются происхождение страницы и адрес назначения формы. Секреты вводятся напрямую в поля Playwright. Модуль не возвращает их другим частям программы. `.env` читается конфигурацией при обычном запуске; импорт модулей и тесты его не читают.

В модель передаётся только текст вопроса/таблицы/формул и варианты с локальными ID. Поля формы, реальные Moodle имена/значения контролов, скрытые session keys, профиль, меню, URL и HTML не передаются. Для визуальных вопросов передаётся PNG области `.content` конкретного вопроса, без шапки и боковой панели. Изображение может содержать само условие и уже видимый ответ. Для другой темы Moodle безопасную область нужно явно адаптировать; полный скриншот страницы не используется как запасной путь.

Codex запускается в отдельной временной папке с `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, отключёнными shell, code mode, MCP, plugins, apps, browser/computer use, memories, skills и subagents. Инструкции из родительских `AGENTS.md` отключены ограничением размера 0. Модель не получает инструменты браузера и доступ к файлам проекта. Переменные окружения дочернего процесса передаются по списку разрешённых системных имён, без `.env` и API/Telegram-токенов. Сам CLI использует собственную штатную авторизацию ChatGPT; её файлы приложение не открывает и не копирует. При неподдерживаемом защитном флаге запуск модели завершается ошибкой без небезопасного запасного режима. Нестандартные корпоративные политики Codex могут ограничить запуск.

При завершении запроса временные PNG, схема и JSON удаляются. Сессии Codex не сохраняются; вопросы всё равно обрабатываются сервисом Codex с правилами вашего аккаунта. Если данные вопросов должны оставаться на ПК, используйте локальный inference-сервер.

Нет записи сырых исключений, HTTP-трафика, тела страницы, tracing/HAR/видео или скриншотов авторизованного сайта в диагностические файлы. `DEBUG`, `PWDEBUG` и `PLAYWRIGHT_DEBUG_LOG` блокируют запуск браузера. Ошибки показываются обобщённо, чтобы сообщение Playwright `fill(...)` не раскрыло секрет. Не включайте внешнюю сетевую трассировку с настоящим аккаунтом.

`cred.txt`, `.env`, весь `data/` и браузерный профиль исключены из Git. Cookies хранятся в `data/session.json`, профиль — в `data/browser-profile-chrome/` (суффикс зависит от канала), база — `data/mentor.sqlite3`. База содержит названия курсов, вопросы/ответы прогресса и историю уведомлений; она локальная, незашифрованная. Не публикуйте эти папки. Защиту от другого пользователя того же ПК обеспечивают права вашей учётной записи Windows; при необходимости ограничьте ACL через свойства папки. На POSIX файлы создаются с `umask 077`.

Панель слушает только `127.0.0.1`, защищена случайным ключом, проверкой Host/Origin и отдельным заголовком POST; не имеет CORS или публичного адреса. Ссылка панели содержит локальный ключ управления: не пересылайте её.

## Настройка Moodle

Селекторы лежат в `config/selectors.json`, путь задаётся `SELECTORS_FILE`. Поддерживаются стандартные Moodle DOM-контейнеры, метки кнопок на английском/украинском/русском, страницы тестов с `attempt` и `page`. Проверяется фактическое наличие элементов; неизвестная структура останавливает действия вместо угадывания. Mentor использован для живой проверки входа, сохранения сессии, мониторинга и обработки вопросов; другая тема или плагины Moodle могут потребовать адаптации. Сроки и остатки попыток остаются неизвестными, если интерфейс не даёт однозначных сведений.

Если курсы не найдены автоматически, укажите их числовые ID из адреса `/course/view.php?id=...`:

```dotenv
COURSE_IDS=123,456
```

Для адаптации откройте нужную страницу в видимом Chromium, используйте DevTools вручную и `/diagnostics`. В отчёте только счётчики совпадений. Исправьте соответствующие селекторы в JSON и перезапустите приложение. Не передавайте разработчику полный HTML, адреса с `sesskey`, cookies, снимок профиля или форму входа.

Ключи: `courses`, `course_next`, `course_more`, `quizzes`, `quiz_info`, `start`, `continue`, `preflight`, `questions`, `question_text`, `answer_region`, `next`, `navigation`, `finish`, `submit_all`, `confirm_submit`, `timer`, `submitted`. Внутри вопроса нужен стабильный `id` или `data-question-id`. Снимок вопроса требует `.content`. Для неизвестных сторонних виджетов, редакторов essay с iframe, загрузки файлов, программирования и недоступных изображений предусмотрена ручная пауза. Вставка HTML, изменение скрытых полей ответа и обращение к закрытым API вместо работы с интерфейсом не используются.

Срок и лимит сохраняются в формулировке интерфейса, без предположения о часовом поясе. Оставшиеся попытки считываются явно или вычисляются, если интерфейс показывает числовой лимит и историю. Неограниченные, скрытые или неоднозначные лимиты остаются неизвестными. Исчезнувший из списка тест не объявляется закрытым без страницы, которая это подтверждает.

## Дополнительный OpenAI-совместимый режим

```dotenv
LLM_BACKEND=openai
LLM_BASE_URL=http://127.0.0.1:1234/v1
LLM_API_KEY=
LLM_MODEL=имя_загруженной_vision_модели
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=1200
LLM_TIMEOUT=180
LLM_RETRIES=2
LLM_JSON_MODE=true
LLM_SEND_TEMPERATURE=true
LLM_VISION=true
```

Для облачного провайдера укажите его HTTPS endpoint и ключ. `LLM_BASE_URL` заканчивается на `/v1`, приложение добавляет `/chat/completions`. Для Ollama с совместимым API обычно используется `http://127.0.0.1:11434/v1`, для LM Studio — `http://127.0.0.1:1234/v1`; сервер и модель запускаются отдельно. Если сервер не поддерживает `response_format`, выключите `LLM_JSON_MODE`; если модель не принимает temperature — `LLM_SEND_TEMPERATURE=false`. JSON всё равно проходит строгую локальную проверку. При `LLM_VISION=false` визуальные вопросы требуют ручного ответа; при явном `UNCERTAIN_ANSWER_POLICY=skip` они пропускаются.

В режиме Codex `CODEX_MODEL` можно оставить пустым для модели CLI по умолчанию. `CODEX_REASONING_EFFORT=high` задаёт effort; `high` также используется, если переменная отсутствует. Приложение явно передаёт значение через `-c model_reasoning_effort=...`, поэтому оно действует и с `--ignore-user-config`. Допустимые значения конфигурации: `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`; выбранная модель и установленный CLI должны поддерживать уровень. После изменения `.env` перезапустите приложение. Более высокий effort может увеличить время ответа и расход лимита Codex. Настройка относится только к режиму Codex.

`LLM_TEMPERATURE`, `LLM_MAX_TOKENS`, `LLM_JSON_MODE`, `LLM_SEND_TEMPERATURE` относятся только к совместимому HTTP API. Таймаут, повторы и разрешение изображений действуют в обоих режимах. Модель Codex должна поддерживать изображения; если нет, вопрос с изображением завершится безопасной ошибкой или должен обрабатываться с `LLM_VISION=false`.

## Модули

```text
src/mentor_automator/
  main.py          запуск, supervision, блокировка процесса и shutdown
  onboarding.py    мастер первого запуска, скрытый ввод и привязка Telegram
  preflight.py     локальная проверка зависимостей без входа в Moodle
  config.py        runtime .env и проверка конфигурации
  auth.py          единственное чтение cred.txt при runtime-входе
  browser.py       видимый Chromium, курсор, сессия и сетевой FinalGate
  moodle.py        discovery, метаданные, навигация и выбор адаптера
  questions.py     разбор типов, безопасные изображения, matching/cloze/order/drag
  markers.py       видимая расстановка маркеров и проверка координат ответа
  monitor.py       периодический мониторинг на отдельной странице
  telegram_bot.py  aiogram 3, long polling, авторизация, outbox и кнопки
  llm.py           Codex CLI и OpenAI-совместимый HTTP адаптер
  agent.py         состояния, пауза/стоп, восстановление, final confirmation
  storage.py       SQLite, ревизии тестов, доставка, прогресс, токены
  events.py        поток снимков состояния без накопления очередей
  errors.py        фиксированные безопасные причины ошибок и названия этапов
  panel.py         loopback HTTP + SSE, управление в реальном времени
  checks.py        runtime-проверки настоящего Moodle и Telegram без вывода секретов
  pairing.py       привязка разрешённого Telegram через одноразовую команду
  models.py        строгие схемы вопроса/ответа/состояний
  privacy.py       очистка текста/URL, запрет небезопасных логов
```

В outbox каждому изменению теста соответствует одна запись. Одновременно найденные изменения объединяются в одно уведомление; новые тесты с неподтверждённой доступностью не рассылаются по одному. Все отправки и редактирования сериализованы с интервалом не менее 1,1 секунды, а `RetryAfter` сохраняет паузу сервера. У Telegram нет ключа идемпотентности для `sendMessage`: после сетевого таймаута нельзя достоверно узнать, дошло ли сообщение. Чтобы не создавать дубли, такая запись становится `uncertain` и **не отправляется повторно автоматически**. Явный отказ Telegram `BadRequest` помечается `rejected`. История доставки доступна через `/diagnostics`; она не смешивается с текущим состоянием агента в `/status`. `/tests` позволяет получить актуальный список явно.

## Проверки

```sh
uv sync --locked --python 3.12
uv run playwright install chromium
uv run pytest -q
uv run ruff check src tests scripts
uv run python -m compileall -q src
uv run python scripts/check_publication.py
```

Тесты используют временные папки, локальный HTTP Moodle-макет и фиктивный файл входа. Настоящие `.env`, `cred.txt`, профиль, университетский сайт и Telegram не нужны. Проверка публикации читает только разрешённые файлы из индекса Git и отказывается открывать запрещённые пути. Тесты браузера работают в headless Chromium, обычное приложение — в видимом Chrome. CI выполняет эти проверки на Linux, macOS и Windows.

Проверки покрывают сессии, дедупликацию, одиночные/множественные/текстовые/числовые ответы, matching, cloze, ordering, перетаскивание и маркеры; картинки в условии и ответах, длинный вопрос с вариантами ниже экрана; смену страницы, неизвестные виджеты и ручную паузу; привязку прав Telegram, пагинацию списка, ограничение частоты; одноразовое подтверждение, потерю связи и восстановление после ошибок. Мастер отдельно проверен на вымышленных данных: скрытый ввод, отсутствие чтения существующего файла входа, отказ при запущенном экземпляре и повтор после неудачной привязки.

На macOS выполнены живые проверки установленного Chrome, входа и мониторинга Mentor, Telegram и Codex; финальная отправка существующей попытки подтверждена переходом Moodle на страницу просмотра после явного разрешения владельца. Правильность ответов и все сторонние плагины этим не подтверждаются. Слишком длинный снимок может ухудшить читаемость мелких картинок; разбиения изображения на фрагменты пока нет.

Дополнительная интеграция с настоящим Codex на вымышленном Moodle включается отдельно и расходует лимит аккаунта:

```sh
# macOS / Linux
MENTOR_LIVE_CODEX=1 uv run pytest -q tests/test_codex_integration.py
```

```powershell
# Windows
$env:MENTOR_LIVE_CODEX="1"
uv run pytest -q tests/test_codex_integration.py
Remove-Item Env:MENTOR_LIVE_CODEX
```

По умолчанию три таких теста пропускаются. Они проверяют сохранение синтетических ответов и остановку перед отправкой, не подключаясь к университетскому сайту.
